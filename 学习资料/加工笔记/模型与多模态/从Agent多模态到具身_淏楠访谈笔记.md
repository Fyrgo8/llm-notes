# 淏楠访谈：从 Agent、多模态到具身

> 一场关于"一年换三条赛道"的对谈实录 · 对话体整理

- **来源**：播客对谈《少有的同时做过 Agent、多模态和具身的人——对谈前混元多模态 RL Infra 负责人淏楠》（转写稿）
- **录制**：2026 年 10 月 25 日，时长约 53 分钟
- **主持人**：发言人 1（嘉宾在对话中称其为"徐总"）
- **嘉宾**：淏楠（发言人 2）。2026 年 1 月毕业，先在 MiroMind 做 language agent 的中期训练与数据，后到腾讯混元多模态，任后训练团队下的 RL Infra 负责人，现为某具身智能公司的预训练负责人

**整理说明**：本文依据转写稿改写为对话体，保留原意与所有关键判断、数字和例子，只做口语化与结构上的润色。转写明显有误或存疑的地方，用「注」标出，未做事实核查。

## 00 开场：先把结论放在最前面

**主持人：** 今天这期比较特别。我们很少聊具身，因为大家做的都差不多，聊不出太多差异性。但淏楠正好完整走过了"Agent → 多模态 → 具身"这条线，一年里换了三条赛道，所以想请你先给没听过的人一个"一页纸版本"：这一年你看到的几个关键判断是什么？

**淏楠：** 我尽量短。

第一，**职业选择**。2025 年底我意识到，Agent 这一年大概率以造数据为主干，对个人积累不太有利，于是转去混元做 RL Infra；后来为了做"生产力方向"的 physical AI，又转进了具身。

第二，**国内外的 RL 差距，不在代码，在卡**。infra 上的代差没那么大，最大的差距是算力。RL 很费卡，在有限预算下 SFT 刷分效率最高，所以 RL 投入自然就少。

第三，**视频生成没有等来它的 R1 时刻**。年初我们以为有，做了半年发现没有：后训练不存在高效的 scaling law，能力提升仍主要来自预训练和数据。

第四，**视频生成的门槛是"数据 + 产品"**。infra 层面，十来个有经验的人两个月就能做到相对水平，而且开源生态很好；但数据没人开源，走不了捷径，所以得在有产品、能回流数据的地方做，这件事吃资本、吃大团队。

**主持人：** 那具体到今天的能力水位呢？

**淏楠：** Seedance 2.5，满分 100 的话大概 60 分，还在半山腰，做一条短剧仍然很痛苦。

**主持人：** 所以下一步的关键是什么？

**淏楠：** 视频需要像 coding 里 Cursor 那样的 harness、交互中间层。视频的交互成分比 coding 更大，因为视频没有公认的最优解。

再往后几个判断：实时互动视频里，各种加速手段都会让画面更容易"崩"，目前保质量比保实时更好；对"真实时"我偏悲观，因为模型越做越大。世界模型很多人"做得有点迷茫，不知道 for what"，而做具身其实不需要先理解和仿真整个世界。GPT-6 Astra 第一次让大模型直接输出有物理意义、能真正操控机器人的低维动作向量，"有点算"具身的 GPT 时刻。具身初创的打法是：大脑交给大模型，小厂的壁垒是硬件加 System 1 小模型的协同设计。

**主持人：** 那数据飞轮怎么转？

**淏楠：** 小模型先操作，快失败时由大模型接管，再不行由人接管。接管产生的纠错数据最有价值，相当于具身版的投机解码和"软蒸馏"。

## 01 嘉宾背景：一年里换了三条赛道

**主持人：** 先把时间线捋一下。2025 年对你来说是什么样的一年？

**淏楠：** 2025 年是圈内 RL 的大爆发，起点是春节前后的 DeepSeek R1-Zero。到 5 月前大家都在做 RL，一直到 9 月；2 到 3 月 ICLR 截稿前后也都在做 RL，对 Agent 的重视程度非常低。

**主持人：** 你正式入行是在 MiroMind？

**淏楠：** 对，2025 年 7 月到 2026 年 2、3 月，在 MiroMind（转写为"memory mind"）做 Agent，算"特别早一批"。做的是纯 language agent：搜网页、看新闻、读网页、写报告。我主要参与中期训练（mid-training）和 SFT，负责 web search 方向的造数据。当时大家对 Agent 数据长什么样、应该怎么造，甚至 MCP 是什么，都还不清楚。

**主持人：** 什么时候开始想走的？

**淏楠：** 2025 年 12 月。我意识到 Agent 这一年大概率以造数据为主干，决定不继续做。

**主持人：** 然后就是毕业、找工作。

**淏楠：** 2026 年 1 月毕业。找工作时拿到的高 offer 大多是 Agent 方向；2 到 3 月"龙虾"（OpenClaw）爆发，大家都想做 Agent。之后我被"好大哥"王天宇拉去腾讯混元，做图片视频生成（diffusion）方向的 RL Infra，任多模态后训练团队下的 RL Infra 负责人，主推一个统一多模态 RL 的工作（转写为"union 2号/UNL"，疑为 UniRL 一类的名字）。

**主持人：** 现在呢？

**淏楠：** 刚加入一家具身公司，任预训练负责人。目前以预训练为主，后训练偏预研；生产环节的训练和各家具身公司差不多，还以预训练为主，因为行业还没到能把真机 RL（转写为"珍妮 LL"）做得特别好的阶段。

> 注：主持人补充，MiroMind 是一家"相对水下"但圈内人觉得很有实力的公司，最近被 The Information 报道了融资（后半句转写不清）。他还提到，嘉宾当时在"戴老师"（转写如此）那边，而他发现嘉宾待过的好几家公司都相对"水下"。

## 02 Agent：为什么当时没有留下

**主持人：** 去年我们判断多模态和 Agent 是应用落地的两条主线。现在 Agent 的方向已经非常明确，比如 personal agent；多模态大家看得多的仍是实时互动这类方向。你当时为什么要从 Agent 走开？

**淏楠：** 在这个领域，"一年太长了"。2025 年 9 到 10 月看这两条路时，我觉得自己已经能看清做 Agent 一年后会在做什么，所以想去看看多模态能做什么，恰好有机会。到 2025 年 12 月，我更明确地意识到：**如果 Agent 这一年大概率以造数据为主干，对个人积累和成长不是特别有利**，也和自己的兴趣、志向不太匹配。

**主持人：** 可多模态的后训练日常也有大量和数据相关的枯燥工作啊。

**淏楠：** 是，但我转去混元做的是 RL Infra，不是数据。契机是 2025 年底 RL Infra 很火，翁家翌（转写为"翁家毅/王佳怡"，早期在某 AI lab，转写为"CAI lab"，一年后去了 OpenAI）在一次公开分享里讲到这个问题，私下聊也觉得确实重要。所以我自嘲选了一个"可能对自己成长没帮助的事"。

**主持人：** 两边都做过之后，最大的体会是什么？

**淏楠：** 围城。做 Agent 的人觉得"天天洗数据，没劲"；做视频的人被说"video 不体现智力"；做 GUI 的人在年初觉得"GUI 都快黄了"。但我的结论是，两个圈子都有有意思的事可以做。

**主持人：** 那做 Agent 的天然好处是什么？

**淏楠：** 你**在主线上**。Agent 现在看是交互的主线，有的公司（包括六小龙里的一些）完全不做多模态生成。职业上，公司做得不好可以换下一家，你还在主线上。

**主持人：** 做多模态呢？

**淏楠：** 过程更有趣，比如 review 数据时看视频、读模型爬出来的 trace、写规则让它筛；但如果公司不做这个方向，就没有很好的发展路径了。

## 03 RL Infra：国内外差距在卡，不在代码

**主持人：** 我听说国内 RL 和海外差距明显。你这个位置上怎么看？

**淏楠：** **工程实践和 infra 上的代差没那么大**，"并不是我们没写出这一套东西"。最大的原因是没卡：RL 和 deep training 都费卡，导致投入少，整体上就出现了代差。差距来自训练的各个环节，以及你能投入多少卡、能坚持训多久。

**主持人：** 难怪大家更愿意做 SFT。

**淏楠：** 对。对提分来说，假设租某家云一个月、要在一个月内把分数推上去，**SFT 效果最好，暴力刷分能力最强**。

**主持人：** 这段 RL Infra 的经历，你自己收获了什么？

**淏楠：** 个人上，在 infra 圈学了很多知识；对公司，这套东西当时在往主线推，希望 diffusion 方向都用上。

**主持人：** 你们组的配置是怎样的？

**淏楠：** 组里有 infra、有算法、有 reward。RL 尤其是图片视频，需要训练一个非常好的 reward 模型，三者绑在一起形成闭环。

**主持人：** 后来你们把多模态往 Agent 方向上加了？

**淏楠：** 对，当时的判断是以 Agent 为主线、做具体 domain。后来做的混元 Creator（转写为"会员 creator"）类似多模态里的 Cursor：

- coding 里，Cursor 会给你生成代码让你 yes/no、写 reject，或者 propose 1、2、3 个方案，第 4 项让你自己填；
- 视频里也可以一次生成三段让你选；都不满意，可以说"我希望用方案 1，再怎么改"。

**主持人：** 为什么这么判断？

**淏楠：** 因为 Agent 是人机交互非常合理的方案，Agent 能力主要来自后训练，所以要围绕 Agent 的整套使用方式去搭多模态；完全不做 Agent 不 make sense。我们的统一多模态 RL 框架也借鉴了很多优秀的开源 RL 库，比如 verl 和 slime（转写为"world/slim"）。

## 04 多模态的分化：理解回暖，生成转向

**主持人：** 多模态内部现在怎么分化？

**淏楠：** 分理解和生成两部分。

**理解**：站在现在看，**GUI 非常火**（腾讯也有相关工作，转写为"5 和 8D"，具体所指不详），GPT-6 Astra 的电脑使用能力非常强，做理解的人"今年又不错了"。

**生成**：下半年基本是在做世界模型，然后有一波人去做具身，包括我自己。我所在的方向是多模态生成，后来去做具身的人分成好几拨。

## 05 视频生成：没有等来 R1 时刻

**主持人：** 2025 年做了一整年 language reasoning，年底到 2026 年初，大家在赌视频生成里有没有 R1 时刻。这个赌注后来怎么样？

**淏楠：** 年初我们认为有，做了半年发现不行，**不存在比较高效的 scaling law**。

**主持人：** 先问一个具体的：Seedance（转写为"c dance"）为什么做得好？

**淏楠：** 我认为和数据质量非常有关系。

**主持人：** 你说的 scaling law 具体指什么？

**淏楠：** 主要指后训练、test-time 的 scaling。语言模型里，大家关心的是 scaling 曲线的斜率（k 值），这和模型结构是否支持高效 scaling 有关；数据可以持续往前推（转写为"能 416 的往前推"，原意不清）。但光靠堆训练是不够的，语言模型要做好 Agent 这类题，还得后面加 RL，才有 R1 那样的效果。我们曾"一厢情愿"地希望在 diffusion 的 test-time 上做到这一点，后来发现不行，加上前面的 caption（提示词）改写也不行，**提升仍主要来自预训练那部分能力**。

**主持人：** 所以视频生成更拼预训练？

**淏楠：** 据我了解，字节（转写为"自己的他们"，疑指字节）的后训练是 work 的，但很多家的 RL 还没 work；即使 work 了，最重要的能力来源仍是前面的预训练。

**主持人：** 那多模态是不是更有巨头效应？

**淏楠：** 我同意，**真的是拼数据**：

- 纯 infra 大家都做得挺好，infra 便宜，十来个有经验的人两个月就能推到相对水平，而且 infra 圈开源做得好；
- 数据没人开源，全看自己的积累，走不了捷径：要么花钱，要么靠产品做数据回流和积累；
- 最后得在有产品的地方才做得成；
- 这个方向更吃资本、吃大团队、吃公司，而不是一波厉害的人就能干起来——"我们是这么尝试过的"。

这也是我没有继续做视频生成的原因之一。

## 06 视频生成的现状：60 分、抽卡与 harness

**主持人：** 最近我常推荐 B 站上的 AI 短剧《被裁掉的女孩》，又刷到更高一个 level 的，觉得"几乎达到 Netflix 的水平"。我还推荐了一部叫《迪超人》（转写如此）的作品，但里面加了很多专业人员的"人工因素"。你怎么看？

**淏楠：** **能力没有到头**，做到接近电影的水平没什么问题。

**主持人：** 那人在创作里还剩什么角色？

**淏楠：** 人还需要参与，但不是像以前那样亲手做很多事，更多是**用你的 taste 影响导向**——这和写代码有点不同。

**主持人：** 你一直强调视频需要 harness。为什么视频比 coding 更需要？

**淏楠：** 视频里做 harness、做 Agent 非常必要，**交互体验的成分大于 coding**：coding 有相对公认的最优解（又快又好、整洁、好读），视频不一样，创作者希望施加自己的影响。不过有些基础能力大家都想要，比如连贯性和可编辑性。现在还是"搞视频、玩视频的人"在用这些工具，还不够便捷。

**主持人：** 你觉得还差在哪？

**淏楠：** 两个方向都还没到位：

- **模型能力**：还没达到电影质感；
- **harness / 交互模式**：没有一款产品能成熟地把电影质感交到普通人手上。

我拿小红书的编辑页面举例，那样就好用很多。未来一定会有一款 harness 或交互式中间层，套在有电影质感的模型上，把能力最大化，让用户最方便地操作——这是我认为多模态生成加 Agent 接下来半年要推进到的水平。

**主持人：** 现在最强的是 Seedance 2.5（转写为"c down 42.5"），它在生成这条线上相当于 GPT 的哪个阶段？

**淏楠：** 满分 100 的话大约 60 分，还在半山腰，空间"非常大"："徐总可以自己做一条短剧试试，操作起来还非常 suffer"，context 管理也不好，各方面都不到位。

**主持人：** 那"抽卡"会一直存在吗？

**淏楠：** 会，但含义会变。现在抽卡是因为有很差的 clip：形变、光线不好。未来片子质量都很好，抽卡是因为你我偏好不同、taste 不同。

**主持人：** 就像线下拍摄时拍好几条给导演选？

**淏楠：** 对，以后不外乎是"你要刘德华还是陈道明"。比如你不想要某种镜头语言，模型却给了，你就要"不要这个、要那个"。镜头语言可以用非常精细的 caption（详细描述）控制，但让人在手机或电脑上敲很长的描述太累，更好的方式是机器根据前面的片段 propose 几种合理的镜头，你来选——这就是 taste。

**主持人：** 开源里有个很火的项目，能快速复制热门视频再换人。过去几年这类东西不少，但都没成为独立产品。

**淏楠：** 这些会成为模型能力的一部分，"模型搞这个并不难"，这就是**理解生成一体化**。我们自己说的 unified（转写为"universal unique"）也是这个意思：理解一定能帮助生成（生成不一定能帮助理解），比如换人需要对影片细节有很好的理解。各家都在推进理解生成一体化。

**主持人：** 视频的终局是什么？

**淏楠：** **生产者即消费者的平台**。现在很多人在消费，但创作的人远没有那么多。不难，大学生也能学会，但麻烦、成本高。未来半年到一年要把使用门槛和成本都拉下来，让更多人生成，形成一个用户既是生产者也是消费者的平台。我很 buy in（转写为"白银"），和圈内人聊下来，大家都认为会出现这样的产品。

**主持人：** 前面提到 H3（转写如此），这款在海外有点火的实时互动模型。

**淏楠：** 它的水平大约相当于 Seedance 2.0，还会生成不少废片；让它 propose 三段，效果不太行，2.5 确实更好。Seedance 2.5 的精细控制能力"挺恐怖"：能放很多参考图、参考视频、参考音频。比如 storyboard：一张图里有很多小图，包括人物正面、背面、发饰等物料和故事线截图，2.5 能按这些图生成一段视频，控制力非常好，H3 就不具备。要落地到商品化，模型就得支持这些输入，产品才能被更好地使用。

## 07 实时互动视频：保质量比保实时更重要

**主持人：** 我把"实时"分成两种：一种是**伪实时**，生成速度快于消费速度，还是你输入完它再生成，只是快到像实时；另一种是**真实时**，真的能对你的对话等做出反应。后者我认为有点像世界模型。

**淏楠：** 大家应该都在第一条路线上，而第一条现在也不成熟，**模型效果崩得比较厉害**，我们曾把这当 research topic 研究过一段时间。

**主持人：** 为什么会崩？

**淏楠：** 加速有很多 trick：调度器（降噪步数）、TeaCache（转写为"tcache"）这类跳层技术（不必每层都做降噪）、各种蒸馏，包括宋飏（转写为"宋阳"）等人的 consistency 模型做一步生成。但这些都更容易让画面崩：镜头转回来后后面的东西变了，或者人脸变了，"转回来之后就给你画了张脸"。

**主持人：** 有点像《盗梦空间》，"有点诡异"。

**淏楠：** 所以目前**保质量比保 realtime 更好**。

**主持人：** 那真实时什么时候能实现？

**淏楠：** 我对"真 realtime"有点悲观：为了一致性更好，模型越做越大，天然就更慢。

**主持人：** 我类比"最近那个 java"（转写如此，指一个舍弃很多东西换来更快速度、更低成本的产品）：主线现在先保质量、保落地，也许做到足够好后会突然出现视频领域的类似产品。

**淏楠：** 时间点很难预测，因为大家攻坚的还是能力，模型还在 60 分，没到能力溢出的时候。

**主持人：** 海外有人把 H3 接入直播间实时生成。

**淏楠：** 我用过，也训过它的后训练，体感上还很慢："如果生成速度真的非常快，我做 RL 也方便了。现在生一个视频要等半天才跑完一圈。"

**主持人：** 你说的第二条路呢？

**淏楠：** 第二条路更像 video world model：用 WASD 键上下左右控制，做 causal 生成，给一个 action 就往下生成一段。最早是 Google 发的（Genie）。最近有些结果很像《塞尔达》，在地图上闲逛"跑图"，但视频质量还不太行。有人在做，但这个圈子最近"又不太火"。

## 08 世界模型的迷茫

**主持人：** 世界模型最近又被骂了。

**淏楠：** 我观察到很多人做得有点迷茫，而且这个领域又受到新的冲击：GPT-6 Astra 用白模加更小的局部渲染（大意是先在 Blender 一类工具里搭出 3D 白模，再做渲染），比"直接出一个巨大的模型仿真整个世界、让你在里面逛"看起来更 promising。

**主持人：** 还有"老大还卖了"的说法，讲了好几年故事，最后不做了。

**淏楠：** 我的说法是：如果真能做好整个世界的仿真和交互，李飞飞站在这个圈子最前沿，为什么要卖公司？她不缺钱，在硅谷号召力也很强（这段转写较乱）。这让大家都更迷茫。

**主持人：** 但世界模型上半年很热、最近降温，我觉得是市场情绪造成的；从研究角度，大家应该一直知道这件事很难、短期做不出来。

**主持人：** 但具身公司也在讲这条路，可能是为了迎合市场。

**淏楠：** 举例来说，World Labs 和 AMI（LeCun 的公司，转写为"word lab 和 MAMI"）都叫 world model，做的东西完全不同。

## 09 为什么转具身

**主持人：** 从视频生成转到具身，技术上是不是要重新学一套？

**淏楠：** 能转，而且**技术迁移很自然**。多模态生成往下走有两条路：一条继续做 diffusion 视频生成；另一条是生成 action，也用 diffusion 模型。从技术角度迁移能力很高、逻辑相近，还能直接用原来的 code base 试一把，也就是做 world action model。最早起步的这批人很多有 diffusion 经验，转型门槛不高。**具身的 action 本身也是一种模态**：就像生成视频的同时生成音频，现在变成视频加 action 一起生成，本质上还是在做多模态生成模型。所以我和身边很多同学都"很丝滑地"转进去了。

**主持人：** 那为什么不留下来继续做视频生成？

**淏楠：** 原因见第 5 节：视频生成里没有 R1 时刻，竞争主要拼数据和预训练，更吃资本和大团队。

**主持人：** 想做具身，为什么不去大厂，而要去创业公司？

**淏楠：** 大厂其实不太能做具身：

- 具身不够赚钱。相对大厂主线业务，它更像车或手机这种产业链很长的行业，不是大厂喜欢的形态；
- 在产业链长的行业里，大厂对产业链的控制力不强，反而像华为这样更懂产业链的公司更合适，"不像软件那样可以暴力推进"；
- 大厂可以做模型研究。如果你觉得行业暂时起不来，在大厂做研究是好选择，很多同学这么想，我也觉得有道理；
- 但真要做具身，就要扎根基层，看数据是怎么弄的，自己上手去遥操两条。大厂分工太细，越大的厂越难去做数据部门的事，"你干了别人觉得你 overhead 了"。

**主持人：** 这是所有领域的大厂通病。

**淏楠：** 同意。

**主持人：** 具身估值已经很高，Astra 又冲击了"大脑"的故事，这个时间点加入没有顾虑吗？

**淏楠：** 很多人问过我。视频方向不是没机会，在初创或大厂都能做，但这和个人偏好有关：**视频不是硬核生产力，是为精神享受服务的**。如果要在同一个行业做十几、二十年，我希望做能影响大家生产力的东西，"说改变人类可能有点抽象"，所以想做 physical AI，把 AI 带到物理世界，"只有到物理领域，你才能改变大家的生活"。这一点我"非常坚定"。

**主持人：** 如果只看短期利益呢？最优选择是什么？

**淏楠：** 当年就做 Agent 了，现在应该在美国。当时 TikTok 美国给了一个相当可观的 package 去做 Agent；他们后来的产品是套在北美 TikTok 的视频上的。那个 offer 确实很诱人。

## 10 GPT-6 Astra 为什么震动了具身圈

**主持人：** 先说基础问题：具身需要什么样的模型？

**淏楠：** 具身模型要能看懂世界，再给硬件下指令。不管是夹爪还是灵巧手（转写为"零销售"），最后输出的是一个**低维向量**，可能二十多维，每一维都有明确的物理意义，比如关节角。这不是大模型同学熟悉的 4096 维那种 latent。

**主持人：** 通俗说，就是机械臂每个电机转多少度。

**淏楠：** 对。模型的输入输出结构是：输入一段或多个角度的视频，经过 tokenize 后进入 transformer，比如经过降噪，输出这样一个小动作向量，是**从高维到低维**的结构。（一般模型可能先输出一个较高维的向量，再映射到动作空间；这里是直接输出转角，部分细节转写不清。）用大模型替代，就是替换中间这个模型：输入视频，输出一串这样的向量。

**主持人：** 以前为什么不行？

**淏楠：** 以前想让语言模型输出动作向量，就是让它自回归地写出"左方括号、第一个数、逗号、第二个数……右方括号"，再把这串数字解析成电机转角。next token prediction 要真的输出"0.96，……"这样一串文字，"有点变态"。一是不自然，二是试了也不 work，之前的模型完全做不到。

**主持人：** 那这次为什么震动？

**淏楠：** Astra 有非常好的理解能力，而且能按指令输出一段真正有意义、能操控机器人的序列。

**主持人：** 是专门为具身训的吗？

**淏楠：** 我认为应该是专门训了具身数据。OpenAI 内部有做具身的团队，也收了很多数据。但据我了解，真正做具身的团队后来"有点不知道怎么做"，发现自己的数据和能力提升最后是在帮 VLM，而 VLM 的提升主要来自 LLM，所有数据最后都回到了语言主线模型上。

**主持人：** 我听说 OpenAI 内部有两条线做具身：一条专门做大模型，把具身当作泛化的一部分；另一条专门做具身。

**淏楠：** 我认为 Astra 主要靠的是大模型那条线：**"堆到主线里反而是最 work 的"**。

**主持人：** 所以本质是泛化？

**淏楠：** 对，就像 Astra 能用 Blender 一样，具身也是"这么推过去的"。关键有两点：

1. 多模态理解要非常强；
2. 这次真的训了具身数据，以前即使有也非常少。

**主持人：** 我总结为两部分：先理解看到的画面，再用具身数据把理解转化成具体的动作向量。

**淏楠：** 当你家主线模型很强时，会发现搞传统 robot learning 不如直接往大模型里堆。

**主持人：** 但各家本体和参数都不一样，需要各自做转译。这个问题怎么解？

**淏楠：** 如果你家产品不是 Franka 这类大家都用的机械臂，而是灵巧手，确实有困难，**灵巧手本身不准**。Astra 的做法很强：动一个关节后观察视觉效果，猜出某个变量的变化代表哪个关节、会带来什么效果，在多轮交互里看明白视觉和输出之间的关系，所以能动得很好（我把它比作 RSI 式的自我探索，转写如此）。

**主持人：** reward 从哪来？比如设定目标是拿到苹果，视觉判断拿到了就算 reward？

**淏楠：** 我认为这是从其他领域迁移过来的，不是对着具身专门训的 reward：在 Blender 任务里，模型看到"这样操作一下，3D 渲染效果会怎么变"，能形成操作和视觉结果之间的关系。用 Blender 时它也是"叮咣一顿操作"编辑出来的，这个逻辑可以迁移。

## 11 数据：仿真还是真机

**主持人：** 数据我分成两类：一类是真机的第一人称（egocentric）数据，另一类是虚拟仿真数据（3D、游戏等）。国内和美国主流都是真机数据。

**淏楠：** 但对谁有价值不一样。对**大模型公司**，仿真数据很有价值，是一个像游戏一样的好环境。对**具身厂商**不是：它们最终在乎能不能落地、能不能操控自家机器，所以要用自家机型连续采各种 trace，不管成功还是失败；失败了用 DAgger 让人接管把它带回成功。

**主持人：** 仿真变强之后，真机数据会贬值吗？

**淏楠：** 我觉得不太会。尤其是灵巧手这种复杂情况，要真正操控成功，还是得用自家机型的真实数据去训、去调。举个例子：抓瓶子，两根手指也能捏起来，但你要的是五根手指贴合在瓶子上抓起来。如果全用仿真环境，最后它可能用中指和食指把瓶子捏起来，不符合你要的效果。这就是仿真的 gap，除非仿真环境做得非常好。

**主持人：** 如果仿真真的做得极好呢？

**淏楠：** 那就回到 real-to-sim-to-real，整个具身的发展路线可能要重新考虑：那条路真的能 scale up，具身厂商和大模型厂商都会走。但**仿真环境非常难做**，World Labs 的路径真不简单，物理的摩擦系数这些都很难仿得够好。

## 12 大脑、小脑与初创公司的出路

**主持人：** 做具身模型的人好像分成两拨？

**淏楠：** 第一拨想做巨大的模型，在 GPT-6 Astra 出来之前国内外都有，国内主要是几家大厂的组：手里有很好的视频生成模型或大模型，想调一调做具身，和 Astra 的逻辑相近。Astra 出来之后，有人就觉得这条路不太有必要了。**初创公司基本不做这条路**：没有技术积累、没有资金、也没有卡。

**主持人：** 市场传闻国内具身公司融了很多钱但真正花的少。具身公司最高估值大约 200 亿人民币，即使融到这个量级，账上可能也就五六十亿，不到 10 亿美元，做不了真正的大模型。

**淏楠：** 所以未来很多公司会拥抱 Astra，这也是具身公司应该做的，最后大概率变成**两个系统**：上面套一个大模型，下面套一个小模型。

**主持人：** 既然大脑的竞争可能变成大模型之间的竞争（国内 DeepSeek 等，海外 GPT 和 Claude），国内具身初创是否不用管大脑，做好小脑和落地就行？

**淏楠：** 我分几点说：

1. 很多公司讲大脑是为了估值，或者说对估值非常有益；
2. 有家公司的主页（转写为"dana"，具体所指不详）写过 System 0、System 1、System 2 的分层。那篇博客是 Astra 之前画的，现在我觉得可能不需要 System 0 了：0 和 1 合成一个，2 就是那个最大的模型。趋势是：贴近本体的 System 1 加上语言和思考能力都非常强的上位大脑（System 2）组合推进；
3. 具身厂商的卡远远不够，"可能要在后面加两个零"，才赶得上大模型厂商。

**主持人：** 大模型这边是所谓的六小龙等五六家在分卡，具身是上百家在分卡，而且分的还是 LLM 剩下的。我去年就觉得具身估值高、有泡沫，没想到今年"更上一层楼"。

**淏楠：** （笑）明年还可以再往上带。

**主持人：** 那初创的壁垒到底是什么？

**淏楠：** **小厂的壁垒是硬件和 System 1 的协同设计**。大厂有大厂的玩法，就是做上面那一套；小厂要有壁垒，要有自己的硬件，否则怎么跟大厂差异化？

- 谁的硬件做得更好，谁能把硬件和 System 1 绑定做得更好，就是 co-design（协同设计）的逻辑；
- 自家产品绑定自家 7B 到 16B 的小模型调得更好，再对接外部大模型，把整套跑通，尽快落地；
- 否则就变成制造业、变成卖货的逻辑了；
- 估值这么高，想要更高，只能真的落地。

**主持人：** 落地有什么具体场景？

**淏楠：** 酒店叠被子。这件事是真的可以做的：酒店地面平，可以用轮式而不是双足机器人；酒店既不是纯标准化也不是完全非标，某种程度上是固定场景，但每次乱的程度不一样。这类场景能做，只要把成本降下来，就能替代一部分酒店整理的工作。

## 13 用大模型搭数据飞轮：接管、纠错与"软蒸馏"

**主持人：** 具身圈一直在等 GPT 时刻（转写为"第三时刻"，可能是 GPT-3 时刻）。Astra 算吗？

**淏楠：** 我觉得"确实有点算"：它真的很强，甚至能替代一部分数采员（转写为"素材员"）。假设它在没训过的场景里泛化成功率只有 50% 到 60%，这已经非常不错了。

**主持人：** 那飞轮具体怎么转？

**淏楠：**

1. 让自家模型去操作，出问题时及时让 GPT 接管：可以有一个监控模型实时看视频，判断"这里要接管了"，把后续操作路由给 GPT；
2. GPT 做完后面的操作，这条接管数据非常有价值，被留存下来；
3. 用这些数据迭代自家的 7B、8B 模型，把成功率从 60% 拉到 80%；
4. 再让它去没人的地方自己采数据，不行再让 GPT 接管；GPT 也解决不了，再由人接管，而且不必一人盯一台，可以一个人盯多台，紧急时再上。

随着成功率提高，**GPT 的调用量变少，人的负担也减小**，scaling up 的逻辑才可能真正成型。所以它可能替代数采，落地时大部分任务自己能做成，实在做不成，大模型或人再上来操作一把。

**主持人：** 你说过这像投机解码。

**淏楠：** 让 GPT 直接操作机械转角不划算，太慢、太费。更可能的形态是一种 speculative decoding（投机解码）：小模型先 draft，大模型只负责 approve 或不 approve。对应到具身，就是小模型先操作，快失败时大模型接管。

**主持人：** 那最关键的数据是什么？

**淏楠：** 纠错数据。这类接管数据也叫 error recovery（失败了怎么回来），是数据里非常有价值的部分，再回流，形成真正能转起来的管线。具身产品很难进入家庭，所以很难像 ChatGPT 那样靠用户使用回流数据；把 GPT 放进这个 loop，当作非常重要的一环，就能推进具身落地。

**主持人：** Astra 的具身能力会不会被其他模型蒸馏出来、开源？是专门的新公司来做，还是被 DeepSeek、Kimi 等做掉？

**淏楠：** 刚才讲的就是一种蒸馏，蒸馏分两种：

- **硬蒸馏**：像语言模型那样让它大量生成 trace 来训。具身里成本太高，没必要；
- **软蒸馏**：机器人操作到一半失败，大模型接管生成的那段 trace 你拿来用。量小很多，而且它把机器人带回正常轨迹，你的模型还能继续操作，相当于只蒸了一两步。成本能 cover 住，数据也很有价值。

软蒸馏大概率是具身厂商在做，而不是大厂，因为具身厂商方便在数采现场部署设备。花的钱和收益是匹配的。

## 14 AI for Science 与收尾

**主持人：** 你相对了解 AI for Science，为什么没考虑？

**淏楠：** 我把做这个方向的人分成两拨：

1. **用 AI 解科学问题**：比如解 PDE、ODE。我以前的老板是 MIT 物理系 PhD，做得很扎实。应用场景举例：在一个有遮挡的大场景里怎么布置 WiFi 信号覆盖最好，是一个很好的优化问题；流体力学等也能用这种方法解。这个方向很有价值，我"不太了解"其价值的全部；
2. **用 AI 帮化学等学科做实验**：这需要实验工厂之类的设施能去做实验，而不只是干实验。

**主持人：** 这就像具身的数采工厂。

**淏楠：** 同意，这一路还需要具身这样的能力才能做成。我不是说这个方向不好，而是在我的认知里，第一拨人在做，第二拨可能还有点早；目前有的公司（转写为"尼克尔"，具体所指不详）夹爪做得比较简单，也可能能行，但具身能力提升了也能帮他们做得更好。

**主持人：** 最后展望一下三条线？

**淏楠：**

**Agent**：智力水平已经完全 OK，关键是怎么让大家更好用，也就是现在主线推进的 GUI 这块。

**主持人：** 我认为 personal AI 是 Agent 这条线的终点。

**淏楠：** 我觉得开发的场景还不够多，想不到下一个爆点是什么，可能要看 Astra 的下一波。很多人会觉得 coding 能力每次都只是"强一点、体验好一点"，很难说清从哪一点提升了，因为大部分情况下它已经超过人类工程师的平均水平。未来还是要推进各种场景，现在覆盖得不够全。

**多模态**：悲观的部分是图片没什么可做的，主要做视频。我很坚定的方向是**视频可控性和视频里的 harness 交互**，未来半年肯定会出现更好的交互式 studio 或 harness，被更多人使用。模型层面主要是大厂竞争：据我了解，没有初创公司在从头预训练视频模型，视频数据很贵。早年做视频的人都爬过 YouTube，我 2024 年底、2025 年初在学校做视频理解时还能爬，现在反爬机制非常严，"一爬就封号"。只有手里有很多视频的那几家可能还能做，小厂做不了。

**具身**：大厂和小厂玩法不同：大厂做上面那一套大模型；小厂靠硬件加 System 1 协同设计的壁垒（见第 12 节）。

**主持人：** 具身在国内从 2023 年起已经三年多，故事变了好几波，估值都很高。Astra 出来后大家又被拉回同一起跑线，有好有坏，但解锁了非常多新的可做的事情。

**淏楠：** 我是兴奋的。Astra 对整个行业是一个非常重要的节点，"第一次让我感觉到，我这东西真的能落地、真的能做"，泛化能力这么强，而且"还都不是 3.5"（大意是这还只是早期版本，后面还会更强）。
