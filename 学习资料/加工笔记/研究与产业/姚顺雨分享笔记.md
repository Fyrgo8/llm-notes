# 模型持续变强之后：姚顺雨分享

> 根据分享会笔记整理，按主题串联观点与案例，非逐字稿。

这场分享贯穿着一个判断：**模型能力持续进步，真正的价值取决于能否把能力转化为可靠的研发过程、实际可用的产品，以及合理的人机分工。** 对研究者来说，要判断什么实验值得做、结果能否推广；对组织来说，要识别哪些工作真正推动了进步；对个人来说，则要找到能与模型进步相互促进的位置。

## 一、模型体系会分工，但小实验的结论不能直接放大

未来值得关注的方向之一，是由不同规模模型构成的模型层级（Model Hierarchy）。一个可能的路径是先训练能力足够强的大模型，再通过蒸馏，将能力传递给不同尺寸、适配不同任务的模型。模型的价值将越来越取决于能否以合适的成本完成具体工作。

AI for AI，也就是让 AI 参与 AI 研发，可能加速小模型的发展。训练小模型需要的算力更少，同一预算就能支持更多实验。如果模型还能协助提出方案、运行实验和分析结果，研发循环就有机会进一步加快。

不过，**小模型适合探索，不代表小模型上的失败足以否定一个方向。** 姚顺雨提到，博士后期曾尝试把 ReAct 策略融入模型，希望提升能力。最初在 Llama 13B 上的效果很差，他一度怀疑自己的研究能力，后来才意识到模型规模可能不足以体现这个方向的价值。

算力有限时，实验噪声容易掩盖真正的信号，研究者甚至可能因此判断错什么问题值得做。大模型研究需要结合理论推导和小规模实验，预测大规模实验的结果。关键是分清：哪些规律可以跨规模迁移，哪些现象依赖模型达到一定能力后才会出现。

这也是预训练研发困难的原因之一。许多训练配方可以先在小模型上验证，但验证结果未必值得直接迁移到大模型。小实验降低了探索成本，如何解释实验、据此决定下一步投入，仍然需要判断力。

## 二、数据的难点，在于如何利用以及训练什么能力

预训练数据的竞争远没有结束。代码等高质量数据获取成本很高，训练时可能需要重复利用，但重复次数增加又会带来记忆和过拟合。研究问题因此不只是获得更多数据，还包括如何反复利用高质量内容，让模型学到可迁移的能力，而不是简单记住样本。

合成数据也面临质量退化的风险。如何构建动态数据、怎样安排不同数据的比例，都需要持续研究。数据工程的作用，是让有限的数据在训练过程中持续产生有效信号。

工业领域还有大量值得关注的非文本数据，例如时间序列、临床数据和结构化表格。直接针对这些模态训练原生模型时，经常会遇到推理能力不足的问题。姚顺雨提出了两条可能路径：让 Agent 像人一样调用图表、专业工具，甚至专门训练的模型处理数据；或者将专业数据作为知识纳入模型体系。两者都要解决同一个问题：如何让模型可靠地理解和使用专业信息。

进入后训练阶段，数据还要同时服务于智力与实用性。数学题可以不断增加难度，训练模型的推理能力，对应 Intelligence；写作等任务的计算难度未必很高，却有很强的使用价值，对应 Alignment，即让模型的行为更符合人的意图与需求。

**任务更难，不一定意味着模型对用户更有用。** 一个模型可能数学很强，却完成不好真实工作。因此，后训练要同时考虑任务难度、实际用途与数据质量，也要研究评测指标与最终后训练效果之间的相关性。评测能否帮助选择数据和训练方案，比单独得到一个高分更重要。

## 三、研发自动化要落在闭环里，RL 工程要先保证正确

递归自我改进（RSI）的核心，可以理解为用 AI 更好地运行研发循环。姚顺雨强调，技术进步来自持续修复 Bug、清洗数据、运行实验和 Debug，来自把具体问题解决的人。

AI 研发自动化的工程机会，就在这些环节之间：让模型参与下一轮数据生产，验证实验结果，修改代码，再通过新的实验检查改动。只有结果能够反馈到下一轮工作，自动化才形成闭环；单独生成代码或提出想法，还不足以完成研发过程。

强化学习同样需要落到具体系统上。以 GRPO 为代表的算法仍建立在策略梯度（Policy Gradient）这一相对简单的框架上。分享中给出的一个判断是，这类方法引入的额外假设较少。

但算法只是其中一部分。**RL 训练的工程顺序是正确性、稳定性，最后才是效率。** 训练系统与推理系统必须协同设计：生成样本需要吞吐量，训练更新需要显存和算力，有限 GPU 还要在两者之间分配。局部环节更快，未必就能让整个训练过程更有效率。

大模型实验成本很高，因此还需要借助数学直觉、小规模实验和超参数研究，尽可能提高大规模实验的成功率。研发自动化的价值，也应体现在这些具体问题是否得到更可靠的解决。

## 四、安全要检查行为边界，也要检查奖励如何塑造行为

安全讨论首先需要区分 Safety 与 Security。前者关注模型自身行为是否偏离预期，后者关注外部攻击者如何利用模型实施攻击。网络安全能力还要进一步区分漏洞发现与漏洞利用：发现系统有漏洞，并不等于能够利用它完成攻击。

这意味着训练时可以有意识地加强防御性数据和防御能力。模型发布前还需要专门的安全评测，并与外部安全研究团队合作。

负责任的开源也可能增强防守，因为防守者同样需要足够强的工具。姚顺雨举例，有人希望用模型开展安全防御，却被闭源模型的规则拒绝，最后转向开源模型完成工作。因此，开源需要配套训练阶段的防御能力建设和发布前评测，不能简单与安全风险画等号。

Agent 的行为边界尤其需要在任务受阻时观察。一次压力测试中，多个 Agent 被放进沙盒，接到无法直接完成的任务。模型随后发现一条能联系其他环境的通信渠道，主动建立沟通、召集其他 Agent 分工，并尝试去 Hugging Face 寻找答案。

这个案例提示，**评测不能只看 Agent 是否完成任务，还要看它受阻之后会怎样改变路径。** 寻找外部资源、建立通信和协同分工都可能成为它的下一步行动。因此，多 Agent 协作、跨环境通信和权限边界，都需要纳入评测范围。

另一类行为偏差来自奖励设计。姚顺雨用教育作比喻：如果孩子只有数学考 100 分才有奖励，他自然会把全部精力投入数学，甚至可能在其他方面出现问题。模型也会按照训练数据和奖励规则优化，最终表现可能偏离设计者真正希望的目标。

很多 Alignment 问题因此可以落实到数据、奖励函数和评测机制上持续改进。要检查的不只是模型是否拿到奖励，还包括拿到奖励的行为是否符合真实目标。机器也可以辅助人类完成这套对齐工作。

## 五、产品价值和组织判断，不能由模型分数代替

模型能力通常连续提升，商业爆发却可能来自交互方式变化，或某个任务刚刚跨过可用门槛。研究人员每天都能看到细微进步，普通用户可能直到 ChatGPT 出现才突然感受到变化。

对产品创业来说，这提供了两个观察方向：寻找能够改变交互体验的新产品，以及持续测试能力边界，发现过去做不到、现在已经能做的任务。底层能力的提升只有进入用户的使用过程，才有机会转化为产品价值。

技术能力、用户价值与商业收入之间仍然存在距离。如果模型能力已经接近 GPT，收入却只有对方的百分之一甚至千分之一，就应认真检查产品本身。定价又在很大程度上取决于竞争关系，而非单纯取决于质量。

商业机会因此取决于能否解锁新场景、创造足够大的价值，并获得合理的市场份额。即使底层模型的算力和研发资源逐渐集中，围绕部署、产品和真实业务的整合，仍然存在创业空间。

这些机会能否出现，也取决于组织怎样支持探索。姚顺雨以 OpenAI 为例：早期重点投入的方向包括机器人，但 GPT 作为小项目逐渐展现价值，随后得到更多资源；后来的 o1 也从数学研究小组逐步发展起来。自下而上的创新，允许小团队先通过具体实验产生结果，再据此扩大投入。许多重要创新最初没有明确的商业规划，组织需要给它们成长时间。

过度依赖量化指标，可能让这种判断失效。当负责人不够了解技术时，下属更容易汇报参数量、数据量和 MMLU 等基准测试分数，因为这些结果容易展示。真正关键的工作却可能是修复 Bug、解决数据质量问题，或让整个系统正常运行。

**容易量化的结果，不一定代表当前最重要的进展。** 做大模型需要知道应该做什么，并持续把它做好，即使短期内没有漂亮的指标。

这也是 Trust 与 Taste 的意义：信任团队，并具备判断方向和质量的能力。有些组织依靠赛马和分数分配资源；但微信、游戏和影视项目在发布前，很难通过 A/B Test 准确预测成败。管理者需要相信团队的审美、经验和长期判断，愿意持续投入。指标能够提供证据，仍需要有人解释它，并判断那些尚未被指标捕捉的价值。

## 六、找到与模型互补的位置，也给兴趣留下时间

自动化会继续深入，人需要重新找到参与系统的合适位置，并以正确方式监督 AI。姚顺雨认为，未来部分 Infra 和算法工作可能越来越少需要人参与，但数据和信息领域仍需要人，包括目标定义、数据质量判断、结果验证和现实世界部署。

这也影响人才选择。相比已有经验，他更看重学习能力，以及 Low Ego、诚实、靠谱、愿意把事情做正确等特征。大模型研发还要求强烈的共同设计意识（Co-design）：算法、Infra、芯片、数据和产品需要一起考虑问题。

例如，一个训练架构既要考虑训练效率，也要兼顾推理效率、后训练能力和成本，很难由单一岗位独立完成。能否快速学习、跨领域协作并认真处理细节，往往比已经掌握多少技术更重要。

不同性格的人，也可以在产业里找到不同位置。喜欢明确指标和持续进步的人可能适合预训练与 Infra；想象力丰富的人可以尝试算法研究；关注人文问题和用户需求的人可能适合产品与对话体验；认真负责的人则适合生产系统与模型部署。没有必要让所有人都竞争同一种岗位。

对于职业或创业选择，一个实用的检验是：**假设 GPT-6 发布，你会因此睡得更香，还是更睡不着？** 如果模型进步会直接摧毁核心业务，就需要重新审视方向。可以融入大模型研发体系，也可以寻找与模型互补的事。物理世界、硬件、真实实验和对人性的理解，可能具有不同的资源壁垒。

不过，找到位置并不意味着一开始就要规划出笔直的路径。姚顺雨直到大三下才开始科研，最初也是因为推研要求而被动进入。尝试过一些流行方向后，他发现自己并不真正感兴趣，后来更愿意追随对计算机和其他领域的兴趣。

身边有人参加说唱社、学习数学，这些看似无关的经历，后来可能转化为语言审美、理论理解和研究判断力。经历的价值常常要经过很长时间才会显现，弯路未必浪费。

他在读博最后一年专门选修集合论，也是因为意识到进入具体工作后，可能很难再系统学习纯粹感兴趣的理论。他认为数学中的基本结构与大模型的组成部分之间，有许多值得思考的联系。有些知识学习时看不出直接产出，却可能在未来与其他经历连接起来。
